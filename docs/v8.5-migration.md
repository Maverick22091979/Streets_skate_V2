# Migrazione Street Skate v8.5

La migrazione è additiva: all'avvio l'applicazione crea, tramite SQLAlchemy, le tabelle `official_skate_rules`, `calendar_events`, `calendar_sync_state`, `official_skate_candidates`, `official_skate_segments`, `official_skate_decisions` e `verified_surface_areas`. Non modifica né elimina righe delle tabelle `routes`, `users` o `auth_connections`.

Prima dell'implementazione è stato creato un dump PostgreSQL locale e un archivio dei sorgenti in `backups/` (ignorato da Git).

## Configurazione obbligatoria per le integrazioni esterne

Inserire i secret seguenti in `docker/secrets/` e i relativi riferimenti nel file ambiente:

```text
google_calendar_api_key
smtp_password
```

Impostare inoltre `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_FROM_EMAIL` e, se necessario, `SMTP_USE_TLS`. Per Aruba usare i parametri SMTP forniti dall'account Aruba; non inserire la password nel repository.

`GOOGLE_CALENDAR_API_KEY` deve poter leggere il calendario configurato in `GOOGLE_CALENDAR_ID`. Dopo averla impostata, un amministratore avvia la sincronizzazione da **Pattinate ufficiali**. La prima sincronizzazione legge gli eventi dell'anno corrente; le successive usano il token incrementale restituito da Google.

Le date di inizio/fine del periodo COVID non vengono dedotte: vanno configurate nella tabella `official_skate_rules` dall'amministratore prima di usare la classificazione storica per quel periodo.

## Avvio

```bash
docker compose up -d --build
docker compose ps
```

Per la produzione usare `docker compose -f docker-compose.prod.yml up -d --build` dopo aver aggiornato `.env.production` e i secret sul server.
